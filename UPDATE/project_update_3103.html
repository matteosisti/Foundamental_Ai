Our codebase — src/
src/models/eomt_wrapper.py

Robust wrapper around EoMT. The original EoMT code uses bare absolute imports (from models.xxx import ...) that break when called from outside the eomt folder. The wrapper fixes this at runtime via module aliasing in sys.modules, strips common key prefixes (network., model., module.) from checkpoint state dicts, and loads only parameters with compatible shapes — making it compatible with checkpoints in different formats without touching original files.

src/runners/ — ERFNet + EoMT eval runners

Full evaluation pipeline rewritten from scratch for both models. Fixes the critical input tensor bug in the professor's original script (see Fixes section). Each runner supports --save-logits to cache raw logits to disk for offline temperature sweep reuse, and produces structured artifacts with timestamped run directories.

src/runners/ — temperature sweep scripts

Offline temperature scaling sweep. Instead of re-running the full model forward pass for each temperature value, these scripts load cached logits from disk and recompute metrics instantly across all temperatures. Run discovery is fully automatic via regex parsing of timestamped artifact folder names — --use-latest finds the most recent valid run with the correct logit cache files on disk.

src/utils/
ood_dataset.py

Unified GT mask loading and remapping for all 5 datasets. Fixes LostAndFound double-remap corruption.

eomt_post.py

All EoMT anomaly scoring functions (MSP, MaxEntropy, MaxLogit, RbA) — single source imported by runners and sweeps.

ood_metrics.py

Vectorized FPR@95TPR via cumulative sum sweep. Single implementation used everywhere.

artifacts.py

Structured experiment logging with timestamped run dirs, config saving, and regex-based run discovery.

determinism.py

Full reproducibility: seeds, TF32 disabled, cuDNN deterministic, CUBLAS_WORKSPACE_CONFIG.

Fixes from the original codebase
Image tensor bug

The professor's evalAnomaly.py applied permute(0,3,1,2) after ToTensor(), which already produces [C,H,W]. After unsqueeze(0) the shape is [1,C,H,W] — the permute transformed it into [1,W,C,H], feeding garbage data to the model. Removed entirely in our runners.

MaxLogit for mask architectures — I fixed my old version implemented from scratch

The original sweep used I wrote log(pixel_probs) as a proxy for logits, which is mathematically incorrect: those are log-probabilities of a softmax-normalized distribution, not raw logits. The correct implementation aggregates raw class logits into pixel space weighted by mask probabilities before taking the max, preserving the pre-softmax scale. Formula: pixel_logits[c,h,w] = ∑_q sigmoid(mask_logits)[q,h,w] · class_logits[q,c], score = 1 - max_c(pixel_logits). This produced significant improvements across datasets.

24% → 71% AuPRC Road Anomaly

LostAndFound remapping guard

Some LostAndFound mask exports are already in binary {0,1} format while others use the legacy multi-class encoding. The original code always applied the legacy remapping, corrupting already-binary masks by inverting InD and OOD labels. Added _is_already_binary_ood_mask() detection guard.

num_classes convention

EoMT adds +1 internally for the no-object token, so class_head=(20,768) in the checkpoint matches num_classes=19, not 20. Using 20 caused a shape mismatch that left the classification head randomly initialized — confirmed via diagnostic inspection of checkpoint layer shapes.

Determinism

All results computed in float32 with fixed seeds, TF32 disabled on Ampere GPUs, cuDNN in deterministic mode, and CUBLAS_WORKSPACE_CONFIG=:4096:8. Results are fully reproducible across runs.

Infrastructure
GPU A100 80GB
Platform Colab Pro+
Precision float32 / float16 logits
Input res. ERFNet 1024x512 · EoMT 640x640

The A100 was necessary because the temperature sweep loads all logits for an entire dataset into VRAM at once as a single tensor. ERFNet on LostAndFound (99 images at 1024x512) produces a [99, 20, 512, 1024] float32 tensor of ~4GB. On a T4 (15GB VRAM) this causes OOM after the runner has already consumed most of memory. We deliberately chose not to implement batch-wise sweep processing to keep the codebase simple — the A100's 80GB VRAM handles all datasets without any memory management overhead.
